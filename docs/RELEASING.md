# Releases

Use explicit immutable versions. Once an artifact has been distributed, changed bytes require a new version. Update updater/build.gradle.kts and scripts/export_bundle.py together. Run ktlintCheck, detekt, testDebugUnitTest, lintRelease and Maven publication. Record exact results in TESTING.md.

Run `python3 -m unittest discover -s scripts -p 'test_*.py' -v` for the export security regressions. Commit the reviewed source before export. With JDK 21 and ANDROID_HOME configured, run `python3 scripts/export_bundle.py DESTINATION`. Export refuses staged, unstaged and untracked changes, snapshots only committed regular files, and rebuilds Maven artifacts in a fresh temporary checkout with build-cache reuse disabled. It validates the built Maven identity and archives, records SOURCE_REVISION.txt and per-file SHA256SUMS, and exposes the completed bundle by a final rename. Existing developer build outputs are never packaged. Export does not sign an app or publish anything.

After reviewing that exact revision and outgoing file list, tag it `vX.Y.Z` and publish the complete Maven/source/license bundle and SHA256SUMS on the matching GitHub release with the owner's approval. Tag, SOURCE_REVISION.txt and source bundle must describe the same code. Mark candidates prerelease while signed platform/physical-device acceptance remains pending. Never include caches, local.properties, credentials or app APKs. Gradle dependency caches remain a build trust input; inspect dependency updates and use checksum verification in consuming projects.

Consumers download the release bundle, validate its SHA256SUMS, and vendor the immutable Maven repository and corresponding source. Gradle must check all pins and reject unlisted Maven files. Publication does not automatically update Kura/Raiun pins. No Maven Central availability is claimed.
